# GaryHub v2.4.4.0 · 个人网站导航

发布日期为 2026-11-26（America/Chicago），安装包为 v2.4.4.0-r1。源码基于 v2.4.3.4 的合并提交 `4603993`（PR #55）。本版已在独立工作区完成源码和本地验证，生产版本以安装器现场输出为准。

## 打开网站

从 Tools 选择「个人网站导航」，点击「添加网站」，也可以直接拖入文件。导航页采用暖纸色、手绘封面与中文衬线标题。桌面使用右侧抽屉，手机使用底部面板。网站名称支持搜索、改名和移除。

| 来源 | 选择方式 | 打开后的行为 |
|---|---|---|
| 单个 HTML | 选择 .html 或 .htm 文件 | 适合自带样式和脚本的单文件网页。有配套文件时可改选整个目录。 |
| 网站文件夹 | 选择包含首页和资源的目录 | 保留文件夹内的路径关系，优先列出 index.html。选择其他 HTML 即可更换入口。 |
| ZIP 网站 | 直接选择普通 ZIP | 浏览器在本机读取，无需手动解压。可以进入多层子目录里的网页，并沿相对链接打开其他页面、图片和 PDF 指定页。 |
| 网址 | 粘贴 HTTP 或 HTTPS 地址 | 点击名称打开该网址。使用 localhost 时，原设备上的服务需要正在运行。 |

首次打开默认不勾选「保存到我的导航」。访客可以直接临时阅读。登录后勾选保存，服务器仅存书签名称、来源类型、相对入口或网址及必要的维护记录。HTML、ZIP、课件和文件授权留在本设备。一个 34 MiB 的课程 ZIP 不会产生一份 34 MiB 的服务器副本。移除导航只移除书签和对应提醒，原文件仍由操作系统管理。

## 再次打开与授权提醒

- 在支持保存文件授权的桌面浏览器中，用「选择 HTML / ZIP」或「选择文件夹」关联一次。下次点击名称，浏览器会在已有读取权限下打开当前文件。导入 ZIP 后，实际关联的是原 ZIP 及其内部入口。
- 原设备登录后，在 Tools 首页或导航页打开、回到前台及页面可见期间定期检查本机授权。首次发现需要重新允许时，在该账号的通知中心「全部」及「工具」分类创建一条未读提醒。「前往个人网站导航」会定位到对应卡片。点击名称重新允许，或点击「关联」重新选取文件。同一设备、同一网站、同一轮失效只提醒一次。重新授权后清除该轮提醒。
- 在新设备或清除浏览器站点数据后，账号仍能看到卡片。首次打开需要选择这台设备上的文件。只支持普通文件选择的浏览器也可以临时打开或保存书签，下次打开本地书签需重新选文件。网站关闭期间，服务器无法检查本机的文件授权。
- 在设备之间同步的是书签。移动了文件或修改了 ZIP 内的入口时，可以保留原名称并重新关联。需要运行后端或依赖在线脚本的项目，可先启动本机服务，再用「网址」添加本地地址。

## 开发定位

- `calendar-app/site-navigator.js` 管理书签和失效记录。接口按当前账号隔离，更改操作沿用 Origin 与 CSRF 检查。书签用修订号处理并发修改，失效状态用账号、书签与本机关联标识去重。
- `lab-service/public/useful/site-navigator/` 包含界面、文件来源、授权检查和阅读器。正式网页在隔离的 iframe 内运行。本地脚本在该环境中无法读取 GaryHub 的账号 Cookie 或文件句柄。
- 普通 ZIP 支持 stored 和 DEFLATE，限制为压缩包 96 MiB、单项 48 MiB、展开总量 192 MiB、条目 4096。原 Markdown Viewer 保留原限制。手机和桌面都可走普通文件选择，选择器能否记住文件取决于浏览器能力与权限。
- 通知中心复用 `calendar-app/hub-api.js` 与 `lab-service/public/hub-account.js`。本版另有一条 `tools` 范围的正式更新通知，安装器切换通过后按既有发布规则发送。

## 安装与回滚

1. 完整解压升级 ZIP，进入 `GaryHub-v2.4.4.0-r1`，在配置过原更新器的 Windows 电脑上双击 `RUN-UPDATE.cmd`。
2. 更新器检查两服务的实际版本均为 v2.4.3.4，识别含／不含 TOTP 的能力组合并核对有效 Compose、源文件、挂载和 Caddy。随后基于正在运行的镜像离线构建，执行 21 组隔离检查、备份、切换和正式 HTTPS 验证。
3. 收到 `8/8 COMPLETE GaryHub v2.4.4.0` 后可确认服务切换完成，现场日志同时给出正式通知人数。需要撤回应用更新时双击 `ROLLBACK.cmd`，按既有机制恢复上一版应用和有效配置，保留当前用户记录。书签在重新升级后可继续使用。
4. 源码同步另有 `PUSH-TO-GITHUB.cmd`。它在独立工作目录创建审查分支，main 的合并由维护者完成。

构建入口为 `python scripts/updater/manage.py build --release 2.4.4.0 --output <新的ZIP绝对路径>`。验证范围见[本版测试记录](GARYHUB_V2_4_4_0_TESTS.md)。
