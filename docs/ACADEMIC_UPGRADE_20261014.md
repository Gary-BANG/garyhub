# GaryHub · Grade Planner & Study Hub

版本：20261014-academic-v1

## 你需要做的三步

1. 将 ZIP **完整解压**到一个普通文件夹。
2. 双击 `RUN-UPDATE.cmd`。如提示 SSH 密钥口令，输入原来的口令。
3. 等待 `7/7 COMPLETE`，刷新 Tools，进入 Grade Planner 或 Study Hub。

不需要复制应用代码、不需要新域名、不需要填写模型 API Key。安装使用现有 Windows OpenSSH 和 `%USERPROFILE%\.ssh\garyhub_interserver_ed25519`。服务器仍为已有 GaryHub 服务器。程序采用严格主机密钥检查，不会自动信任未知主机。

生产网站尚未由本开发环境更新。安装程序将在你的服务器完成实际构建、备份、切换和 HTTPS 检查。请将最后的 COMPLETE 或 STOPPED 输出发回，以便确认实际结果；无需发送密钥、配置或数据库。

## 两个新入口

- Grade Planner：`https://tools.garyhub.uk/grades/`
- Study Hub：`https://tools.garyhub.uk/study/`

沿用 GaryHub 登录身份；共用个人课程目录，每用户独立数据。既有共享登录配置保留；旧版账号架构也可使用新模块的登录表单。

## Grade Planner

- 课程名称、学期、1/2/3/4 学分；可选择是否计入 GPA。
- 自定义成绩组成及占比：Homework、Quiz、Midterm、Final 等。
- 得分和满分分别录入；空白为未评分，0 是实际零分。
- 单次评分、子项等权、按总分累计、自定义子项权重。
- 预计子项总次数和未添加子项满分，让尚未公布的作业参与剩余成绩预测。
- 自定义等第门槛、门槛满分和等第绩点；个人默认模板仅应用于新课程。
- 当前已评分平均分、已获得总评分、最终等第，以及点击目标等第后的剩余所需平均分。
- 独立模拟分数；勾选“纳入模拟分数”后可固定预期结果再预测其他待评分项目。
- 已结算 GPA、模拟 GPA；输入既有学分和 GPA 后计算累计值。
- 课程权重须合计 100%；自定义子项权重也须合计 100%，才能形成有效最终总评。
- 分数不能高于该项满分；本版未加入额外加分、自动 curve、drop-lowest、重修替代或学校专用舍入规则。

按总分累计模式下，尚未添加的作业满分使用你设置的“未添加子项默认满分”；如果各次满分不同，应先逐项列出待评分作业，保证预测分母准确。

## Study Hub

- 上传单个/多个 Markdown、文件夹或 ZIP；支持 PNG、JPG、GIF、WebP 图片。
- 保留相对图片和讲义链接；自动去除所有文件共同的最外层文件夹。
- 按 Lecture 数字自然排序，也可编辑标题与排序数字。
- 未学习、学习中、已学习状态及阅读位置保存。
- 日夜主题、字号、行距、阅读宽度；代码显示、本讲目录、Markdown 表格。
- KaTeX 本地资源：行内 `$...$` / `\(...\)`，块级 `$$...$$` / `\[...\]`；错误公式显示原文。
- 远程图片不自动访问；请随文件夹/ZIP 一并上传图片，或将图片存入所选 GitHub 课程目录。
- GitHub 公共或私有仓库只读导入，选择所有者、仓库、分支、目录后手动同步。私有仓库令牌只用于本次请求，不存储；每次同步需重新填写。
- 同路径讲义更新内容并保留进度；内容 SHA 唯一匹配时识别重命名；源文件被删除时保留个人副本并标注。
- 首版每次导入最多 500 个文件、12 MB，单文件最大 4 MB；每用户全部讲义/图片约 20 MB 上限（图片按 Base64 存储体积计算）。超限会明确提示。
- 大型或被 GitHub 截断的仓库目录会拒绝不完整导入，请使用较小课程仓库/上传文件夹。分支默认 main，可自行更改。

## Calendar 联动

在 Lecture 顶部点击 Add to Calendar，弹窗预填：

- 标题：`学习 课程名称 Lecture 标题`。
- 备注：`课程名称 Lecture 标题`。
- 开始和结束日期：Calendar 账号时区的当天。
- 邮件提醒：默认关闭；需要时可勾选并设置每天提醒时间。

点击保存才创建事项。关联列表支持打开 Calendar；已完成的安排可通过“查看安排”标记本讲已学习。再次添加允许创建复习安排。

重复点击同一请求不会重复建事项。如果在 Calendar 已处理后网络中断，程序会提示先检查 Calendar，不盲目重试，以免产生重复安排。已有日历事项的编辑通过 Calendar 完成。

## 数据及安装范围

新数据保存在已有 Lab 持久化目录下的 `academic/`，不覆盖 `user-*.json` 练习进度和网络授权文件。每次写入绑定登录用户、检查 CSRF 和来源、验证账号 ID 与数据修订号；管理员不会获得查看他人学习数据的额外接口。

安装只更新现有 `garyhub-lab` 镜像：新增模块，在原服务器代码中加入独立路由，在 Tools 页面加入两个入口。Calendar 数据库、提醒 worker、Caddy、其他容器不进行代码切换。

升级流程：
1. 检查文件完整性和已审阅的生产源码版本。
2. 在当前实际镜像基础上离线叠加代码，保留环境变量、挂载和网络。
3. 用临时账号、隔离数据和模拟 Calendar 运行 HTTP 检查。
4. 短暂停止 Tools/Lab，创建并验证完整数据备份。
5. 切换新镜像并检查健康状态。
6. 检查正式 HTTPS 页面及未登录访问返回 401。
7. 保存部署记录并输出 COMPLETE。

Tools、Lab 和 Network Access 共用容器，切换时会有短暂不可用。更新前保存正在编辑的内容。

若实际 `server.cjs` 或 Tools 首页不匹配读取过的两套版本，安装会停止并列出文件名，不覆盖未知改动。

服务器记录：`/opt/garyhub-update-20261014-academic-v1/deployment-state.json`。
受限备份和日志位于同目录 `private-backup/`，包含私人数据，保留在服务器，不要发到聊天或 Git。

## 回滚

双击 `ROLLBACK.cmd`。恢复旧的 Tools/Lab 镜像，保留目前所有用户数据，包括新学业模块数据。若之后又部署了其他版本，回滚会停止，避免覆盖后续工作。
