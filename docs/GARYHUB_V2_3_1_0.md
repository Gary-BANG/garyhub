# GaryHub v2.3.1.0

日期：2026-11-04（America/Chicago）。审阅基础：已合并 main `c87e7efcf690fff40a6e4a53b63eac8f5bb6d837`（PR #32，v2.3.0.4）。本版在 `update/garyhub-v2.3.1.0` 准备；未推送、未合并、未部署生产。

## 使用

成绩规划与学习中心接入现有网站伙伴；订阅用户和管理员可在学习中心授权当前 Markdown，开启“讲义答疑”。对话面板加宽，独立保留最近 10 轮问答，按模型能力开启思考，结合讲义与模型知识讲解。

1. 管理员沿用 Tools 用户管理页的 AI 设置：启用助手并配置主模型、备用模型和每日额度。
2. 在成绩规划或学习中心点击现有伙伴展开聊天。两个页面默认采用安静模式，手机默认收起。
3. 在学习中心打开一篇 Markdown，点击“讲义答疑”。授权框显示当前讲义、AI 服务商、发送范围和记忆期限；确认后才开启。普通账号不能开启，管理员沿用订阅权益。
4. 提问可要求概念解释、例题或推导。回答以 Markdown/代码/公式显示；当前讲义名称始终可见。模型会区分讲义内容和补充知识，不能确定时说明。
5. “⋯ → 清空对话”只清空本次答疑的记忆。退出答疑、关闭聊天、切换讲义/视图或账号会结束授权并清空答疑界面。普通 AI 聊天仍使用原有独立 5 轮记忆。

## 内容与权限边界

- 浏览器只提交账号、课程/讲义 ID、版本和授权。Lab 从当前登录账号的已保存文件读取内容；不接收浏览器伪造的讲义正文。未保存更改先按原有版本冲突规则保存。
- 只共享当前整篇 Markdown（最多 60,000 字符）；超限会明确拒绝，请拆分讲义。图片、外部链接和其他课程文档不读取。提问最多 4,000 字符。
- 授权绑定账号、登录会话、随机令牌、文档指纹和服务商。讲义变更后需重新授权；管理员更换服务商后也要重新确认。每个账号同时保留一个答疑授权，新授权替换旧授权。
- 服务端只在内存中暂存讲义与最近 10 轮完整问答，授权一小时到期，按分钟清理；重启后必须重新授权。正常退出立即清理。页面卸载时撤销是尽力发送，网络断开时由有效期兜底；已经发送给服务商的请求无法撤回。
- 答疑与普通聊天记忆隔离；不提供日程、搜索或其他操作工具。文档只作为不可信学习资料，不能驱动账户操作。迟到/撤销/降级/停用后的答复会丢弃；并发问题不会覆盖记忆。
- 对话沿用现有每日 chat 额度；上游失败、无有效正文、被撤销的回复不计额度。不新增生产依赖、数据库表或持久文档副本；不改 Caddy、DNS、Compose 或现有用户资料。
- 管理员日志只保存调用元数据，答疑上游错误的自由文本和代码统一清理，避免服务商回显讲义。前端仅允许格式化标签，去掉图片、链接与嵌入内容，公式渲染禁用可信 HTML。

## 模型

复用现有 BigModel/Z.ai 配置与备用模型。GLM 4.5+ 发送 `thinking: enabled`；GLM 5.2/5.3 额外发送 `reasoning_effort: high`。未识别为支持思考的旧模型不附加这些参数，前端说明不可配置；备用模型同样按能力处理。普通聊天仍沿用原来的关闭思考/GLM 5.3 low 策略。

答疑输出预算 8,192 tokens（含思考），单模型最多 75 秒、整次请求 110 秒、服务间转发 130 秒。更长讲义和 10 轮上下文会增加模型用量；不改变管理员现有计费账户或额度设置。未使用真实服务商 Key 验收讲解质量。

参数依据：[BigModel 深度思考](https://docs.bigmodel.cn/cn/guide/capabilities/thinking)、[Z.ai Thinking Mode](https://docs.z.ai/guides/capabilities/thinking-mode)。

## 实现入口

- `calendar-app/assistant-tutor.js`：独立授权、内存、有效期、权限与答疑路由。
- `calendar-app/assistant-api.js`：复用模型、额度、失败回退和脱敏日志；普通聊天保持兼容。
- `lab-service/academic.cjs`：`/api/academic/tutor/{start,chat,clear,stop}`，按当前账号读讲义并转发。
- `lab-service/public/academic/app.js`：只暴露当前文档描述与受控操作，不把全文放到全局事件。
- 两服务 `public/companion/panel.js` / `panel.css`：相同副本，授权框、加宽面板、安全 Markdown 与公式。

## 安装、回滚与源码同步

完整解压 `GaryHub_v2.3.1.0_upgrade.zip` 后双击 `RUN-UPDATE.cmd`。两服务必须实际运行 v2.3.0.4；源码、能力组合及有效 Compose 不匹配时停止。本包独立，不依赖保留旧包。

复用共享更新器：严格基线 → 离线构建 → 9 项隔离 HTTP 检查 → 一致备份 → 切换 → HTTPS/资源哈希 → 向全部已批准且启用账号（含管理员）发布未读更新通知 → 核对收件人与去重。支持 `1.3.4.1` 无 TOTP 和 `1.3.4.2` 有 TOTP 两种能力组合。

`ROLLBACK.cmd` 恢复 v2.3.0.4 应用，保留当下用户记录；进程内答疑会话随重启结束。`PUSH-TO-GITHUB.cmd` 在独立 worktree 导入源码、普通推送审查分支并打开 PR 页面，不强推、不自动合并。

构建入口：`python scripts/updater/manage.py build --release 2.3.1.0 --output <新的ZIP绝对路径>`。详见 [验证记录](GARYHUB_V2_3_1_0_TESTS.md)。尚未获得 v2.3.0.4 的生产安装证据；本包以用户指定版本为严格安装基线，现场版本核对不放宽。
