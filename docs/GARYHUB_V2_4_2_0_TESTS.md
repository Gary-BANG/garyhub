Calendar 新增的 `games.test.js`（5 项）：

- **开局**：奖品数量、金额范围与整数分、礼品名称与图标、币种、第一轮盒子数的校验；按用户名邀请，不能邀请自己、不存在或已停用的账号；每人最多同时发起 5 局。服务器保存的顺序是 0…N−1 的排列，指纹等于 `SHA-256(盐 | 顺序)`；双方看到的数据都不含顺序和盐；参与人在选盒前就能看到第一轮盒子数。
- **完整对局（多轮）**：错误的一方 403、过期修订号 409、越界盒子 400、未知动作 404；揭开数量必须正好等于本轮要求，不能含自己的盒子或重复；出价时“下一轮揭开数”在 1 到剩余−1 之间，只剩一个别的盒子时是最后一次出价；拒绝后进入下一轮；揭晓时先开其他盒子，最后才能开参与人的盒子；结束后公开的顺序与指纹一致，过程中揭开的每个盒子与公开顺序一致；只有发起人能标记兑现，且只能一次。
- **直接出价、成交、取消与婉拒**：两次同时揭盒只有一次成功（另一次 409）；发起人只能在参与人选盒前取消；婉拒后不能再选盒；双方在正确时刻收到对应通知。
- **通知与清理**：关闭“事项提醒”推送的账号只收到站内通知；30 天无进展的对局过期；参与人账号被删除后，每小时清理移除对局。
- **HTTP**：未登录 401、账号不一致 409、非参与者 404、无效编号 404、错误以 JSON 返回。

## 浏览器检查（本地合成数据）

在本地栈中新增游戏主机入口（端口 3105，Host 为 `games.garyhub.uk`），以 `check_alice`（发起人）和 `check_bob`（参与人）分别操作，另一方由脚本经 Calendar 接口操作。

- **游戏厅**：登录后显示账号名与白日梦想家卡片；未轮到时徽标为“新游戏”，有轮到自己的对局时显示数量。
- **建局**：“经典金额”与“金额 + 礼品”预设；礼品图标选择、名称与估值；奖池预览按金额高低分两列、礼品按估值排列；第一轮盒子数步进器上限为 N−2；提交后进入对局页。
- **发起人视角**：等待参与人选盒时可取消；对方揭开后页面在 8 秒内自动刷新，被揭开的盒子依次翻面，奖池对应项划掉；出价表单显示未揭开数、平均值与最高值，下一轮盒子数步进器上限正确；对方成交后进入揭晓阶段，可手动点开或“依次自动揭开”，自动揭开在参与人的盒子前停止；最后揭晓时出现开盖动画与彩带，结论“盒子比报价更值——这笔你赚到了！”与“参与人获得 ¥320”正确；封箱指纹显示 ✓。
- **参与人视角**：“我的对局”按“轮到你／等待对方／已结束”分组；邀请页说明第一轮要揭开的盒子数；选盒、点选要揭开的盒子（已选 x / k）、揭开；信封式报价显示金额与附言，按钮为“成交”和“不卖，再揭开 3 个”。
- **语言与外观**：中英文切换（标题、按钮、动态文字），日夜切换；英文下金额显示为 ¥ 而不是 CN¥。
- **手机（375 px）**：页面没有横向滚动；页头只保留当前位置；奖池默认收起；盒子 4 列，金额不溢出；邀请与报价操作在盒子下方正常显示。
- **主页**：“更多”菜单出现 “Games”，英文模式下说明文字已翻译；参与人的未读通知数包含游戏邀请。

## 开发中发现并修正的问题

- **选盒前不知道第一轮盒子数**：接口起初只在“揭盒”阶段返回本轮盒子数，参与人收到邀请时页面错误地写着“发起人会直接出价”。已改为邀请阶段也返回，并加入单元测试与隔离断言。
- **操作后盒子不能点**：页面在请求完成、解除“忙碌”状态之前就重绘，导致刚轮到自己时盒子不可点。已调整顺序。
- **大厅徽标位置**：脚本更新徽标时覆盖了定位用的类名，已改为只切换状态类。
- **手机布局**：页头换行、固定在底部的操作区遮住盒子、“CN¥2,000” 在小盒子里溢出。已改为页头只保留当前位置、操作区随内容排列、金额使用窄货币符号并缩小字号；奖池收起时同时收起过程记录。
- **用户名被转为大写**：对局页眉沿用了大写的小标题样式，已取消。
