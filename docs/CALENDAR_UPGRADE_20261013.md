# GaryHub Calendar 升级 · 20261013-calendar-v1

本包已完成开发和本地测试。服务器上线由安装程序执行；拿到文件并不代表服务器已经升级。

## 你只需做什么

1. 把外层 ZIP 解压到一个普通文件夹，不要在压缩包内部运行。
2. 双击 `RUN-UPDATE.cmd`。
3. 如果提示 SSH 密钥口令，输入你原来连接 GaryHub 服务器时使用的口令。输入时不显示字符是正常现象。
4. 等待显示 `COMPLETE` 或 `Already complete`。刷新 Calendar（必要时 Ctrl+F5）。

程序使用你已有的 Windows OpenSSH 和 `.ssh/garyhub_interserver_ed25519` 私钥，不包含私钥、服务器密码或用户数据。沿用之前升级程序中的服务器地址。无需再复制多段代码或配置 Cloudflare。

安装中会有一次 Calendar 短暂停机。先保存页面上尚未保存的编辑。

## 这次完成的功能

- Calendar 冷色动态点线背景、白天／黑夜模式；首次跟随系统，此后记住选择。
- 月历下方五项横向功能栏：事项与分类、新增事项、事项列表、账号与提醒设置、日记与健康记录。默认全部收起，一次展开一项，展开区与功能栏等宽。
- 手机端功能栏可横向滑动。点击日期或事项会打开编辑区。
- 日记独立入口 `/journal/`：可翻月并直接选择年月的日期表，标题筛选，分页列表；列表只显示日期、标题、最右侧心情；点击记录显示正文。
- 心情支持 😊 开心、😌 平静、🤩 兴奋、🥰 感恩、😴 疲惫、😔 低落、😟 焦虑、😠 生气，以及“未记录”。
- 健康独立入口 `/health-records/`：体重、kg/lb 显示切换、趋势、锻炼与周期汇总。
- 暖色登录页 `/login/` 和独立注册页 `/register/`，沿用现有注册审批和邮箱验证规则。
- 原有账号、日记、事项、健康记录继续使用原数据库。旧日记默认“未记录”心情；旧客户端修改日记不会清空已保存的心情。
- 保留管理员查看用户事项及创建用户功能。日记与健康记录仍只允许记录主人访问，包括管理员也不能通过这些接口查看别人的私人记录。
- 日记页面绑定打开时的账号，拒绝跨账号保存；未保存内容离开时会提醒。
- 月历库沿用原有 FullCalendar 6.1.20，改为随站点提供，不再依赖外部 CDN 加载。

## 自动完成的上线步骤

核对正在运行的源码 → 生成保留现有环境和挂载的有效配置 → 基于当前镜像构建 → 隔离数据库和账号测试 → 一致性数据库备份及完整性检查 → 切换 Calendar → HTTPS 检查 → 向全部启用账号发布一条未读站内更新通知（含管理员，重试不重复）。

只更新 Calendar 容器，使用现有子域名和路由。Tools、Lab、VPN、提醒 worker、Files、RSS 和监控不参与镜像切换。

兼容读取过的 10 月 11 日服务器快照，以及同日共享登录更新包。若实际源码已发生其他变化，程序会在部署前停止并列出发生变化的文件；不要绕过校验。把窗口最后的文字发回即可继续处理。

服务器实际执行记录在 `/opt/garyhub-update-20261013-calendar-v1/deployment-state.json`。含配置与数据库的备份留在该目录下的 `private-backup/`，不要上传或提交 Git。

如果应用已上线但通知发布失败，安装器会标记 `notification-pending`。再次运行同一安装程序即可只重试通知，不会重新部署或重复通知。

## 源码

安装器会在 `%LOCALAPPDATA%\GaryHub\updates\20261013-calendar-v1` 保留源码、测试与说明。如果既有仓库 `D:\Codes\Own_Project\garyhub-repo` 存在、干净且与已审阅版本匹配，则自动创建 `update/garyhub-calendar-20261013-v1` 分支并本地提交。不会推送远程仓库；源码同步失败不影响已经完成的服务器升级。

## 回滚

双击外层文件夹中的 `ROLLBACK.cmd`，会通过同一 SSH 连接执行回滚。回滚恢复旧 Calendar 镜像与部署索引，保留当前数据库，包括升级后新增的日记。新增心情字段留在数据库中，旧页面不会显示它。若上线后又发生其他部署，自动回滚会停止，避免覆盖后续版本。
