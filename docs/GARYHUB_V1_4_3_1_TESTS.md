## r3 回滚索引修正与新增验证

用户 r2 输出在第 1/8 步报告 Effective Compose does not match active deployment index，没有开始构建或切换。共享 restore 中的顺序问题已复现：旧镜像通过本次备份 Compose 启动后，Docker 标签指向该备份；原样恢复旧 active.json 却重新指向前次文件。此前回滚夹具只模拟镜像 ID、且主要覆盖无旧索引的情况，遗漏了这条连续路径。

r3 共享 restore 在恢复完成后读取真实容器的镜像／运行／项目／服务／路径标签，对齐索引并严格验证。v1.4.3.1 适配器新增受限 reconcile_active hook：只处理具有准确 r1 清单哈希、完整 rolled-back 记录、未变化索引和两份等价配置的已知遗留状态；核对 Caddy 和容器未并发变化，保存原索引后只原子更新路径。未知情况拒绝；原始版本／来源／配置检查继续保留。

15 项新增回归通过：复现用户的旧路径报错；完整证据修复及再次预检；自动回滚和手动回滚后严格预检；已有用户记录保留；幂等；审计写入后中断可恢复；后续镜像、项目、环境／挂载、索引、包、状态、Caddy、容器并发变化和缺失／符号链接证据均拒绝，索引不被改写；恢复容器标签异常时不发布新的索引。Docker 采用会随 old_up 更新 -f 路径标签的状态夹具，没有本地 Docker daemon，不将模拟结果表述为服务器验证。

共享核心测试现为 35 项通过，既有 host integration 的 10 项回滚／变更保护检查通过；另 2 项生成源码包后的 PowerShell 导入检查在交付阶段执行。两个实际 Node 20 能力组合各 71 项 HTTP、5 个合成通知收件人／去重及真实第 6 阶段本地 curl／Node 哈希校验继续通过。业务页面及应用载荷与 r1/r2 相同，原浏览器验证沿用。共享运行时和受限修复脚本已做 Python 语法检查；最终包需包含该脚本并校验其哈希。

## 最终包校验流程

前置验证完成、源码提交且工作区干净后，使用 `manage.py build --release 1.4.3.1` 生成最终 upgrade ZIP。交付前检查：

- 外层全部 SHA256SUMS、payload 全部 manifest 哈希、安装模板内嵌 payload 校验值、安装／回滚／源码同步入口和 CMD 的 CRLF。
- 两种能力组合的旧源码基线来自上述审阅提交，目标载荷与当前源码／显式能力覆盖一致；没有私有文件、数据库或密钥入包。
- 独立源码补丁可应用，完整文件清单与 Git blob 对应；安装器和源码同步 PowerShell 可解析。
- 用真实 PowerShell 对最终包的源码导入器运行临时本地 bare remote 测试：保护未提交工作、创建独立 worktree、普通 push、main 保持基础提交、重复运行去重、拒绝后续无关修改及损坏补丁。该测试不连接真实 GitHub。

最终 ZIP 是构建产物，不把其哈希反向写入自身。最终校验结果及外部 ZIP 哈希随交付说明提供；本记录不把尚未收到的生产证据列为通过。
