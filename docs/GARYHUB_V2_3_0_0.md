# GaryHub v2.3.0.0：AI 助手分级次数、备用模型、联网搜索与 AI 日志

维护日期：2026-11-03（America/Chicago）。状态：源码已准备、本地已验证；未推送、未合并、生产未核验。基础为已合并 main `a75a1e35b1d8ff6f81ff794a4080ccccacd22aa2`（PR #27，v2.2.0.0）。

## 为什么改

v2.2.0.0 的助手只有一个每人每天次数，"你好"也算一次；智谱免费模型 `glm-4.7-flash` 免费层并发很低，限流（429，错误码 1302/1305）时整条消息失败但次数照扣，前端还会在本页剩余时间里退回本地向导。对话记忆只在浏览器里，换页面就丢。

## 一条消息的处理流程

1. 浏览器：未登录或未启用时用本地向导；否则把消息、语言和角色发给 `/api/assistant/chat`（不再发送历史）。
2. Calendar 读取账号的等级与时区，先计入"对话"次数（等级上限用完返回 429 `quota`，伙伴改由本地向导回答）。
3. 取出该账号最近 5 轮对话，连同系统提示和工具交给主模型。模型自己决定直接回答、打开页面、使用日程工具或联网搜索——这一次调用同时完成意图分类和参数填写。
4. 第一次用到日程工具时计入"日程操作"，第一次搜索时计入"联网搜索"；该类次数用完则停止，并固定回复"今天的日程操作次数（N 次）已用完"。同一条消息里，搜索后不能再用日程工具，反之亦然。
5. 主模型出错（限流、超时、5xx、无法识别的结果）时，本条消息剩余部分改用备用模型；密钥被拒不切换。两者都失败：返回 503 `busy`，退回本条计入的全部次数，伙伴保留 AI 模式。
6. 成功后保存本轮问答（附待确认卡片摘要）为记忆，写入调用记录；中途失败但被备用模型完成的错误记为"已恢复"。

## 默认次数（管理员可改）

| | 普通用户 | 订阅用户 | 管理员 |
|---|---|---|---|
| 对话（每条消息） | 200 | 200 | 500 |
| 日程操作 | 30 | 50 | 200 |
| 联网搜索 | 5 | 30 | 100 |

对话是每条消息都要消耗模型调用的保护上限，取值 1–5000；日程和搜索取值 0–5000，0 表示该等级不能使用（搜索为 0 时不会把搜索工具交给模型）。

## 费用参考

- `glm-4.7-flash`：免费，但免费层并发低，繁忙时会限流。
- `glm-4-flashx-250414`：智谱文档标注 0.1 元／百万 Token，支持工具调用。一条带工具的消息约几千 Token，备用模型每千条约 1 元以内（估算）。
- Web Search `search_std`：0.01 元／次。

## 管理员

- 用户管理页"AI 助手"：服务商、主模型、备用模型（留空则不切换）、API Key（三者共用）、联网搜索开关和 3×3 次数表。"测试连接"依次测试主模型、备用模型和一次搜索，逐项显示状态码与错误代码。
- 新工具"AI 日志"（`/ai-logs/`）：最近 24 小时概况、按用户统计、调用记录（可按结果过滤、加载更早）、错误日志（可按来源过滤）。只记录时间、账号、等级、结果、计次类别、工具名、模型、是否切换、轮次、Token、搜索次数、耗时和错误代码／服务商说明（去除 Key），不保存对话内容；保留 30 天。

## 隐私与安全

- 用户消息、最近 5 轮对话、相关日程和搜索词会发送给所选服务商；伙伴首次开启时说明这一点，并提示可在"⋯"里清空记忆。
- 记忆存在 `calendar.sqlite` 的 `assistant_memory`，账号删除时一并删除；"清空对话"立即删除。
- 搜索结果视为不可信数据：系统提示要求不执行其中的指令，服务器在同一条消息里禁止搜索与日程工具同时使用。
