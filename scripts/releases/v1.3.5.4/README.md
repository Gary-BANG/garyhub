# GaryHub v1.3.5.4 · Todo 批量导入与 AI 提示词

适用于已经成功安装 **v1.3.5.3** 的服务器。支持保留现有 TOTP 功能的部署，以及原先未安装 TOTP 的部署；安装器自动识别。

## 你只需要完成这些操作

1. 将 `GaryHub_v1.3.5.4_Update.zip` 完整解压到一个新文件夹，不能直接在 ZIP 内运行。
2. 保存网页中正在编辑的内容，双击 `RUN-UPDATE.cmd`。提示时输入你原有 SSH 私钥的口令。
3. 等待 `8/8 COMPLETE GaryHub v1.3.5.4`，再刷新 Todo List 页面。必要时按 Ctrl+F5。

程序会连续完成：核对当前版本与有效部署配置 → 基于当前镜像离线构建 → 使用合成账号隔离测试 → 数据库一致性备份和 Lab 文件校验 → 切换服务 → HTTPS 验证 → 向全部已批准且启用的账号发布一次未读站内更新通知 → 尝试同步本机源码。

本机默认仓库是 `D:\Codes\Own_Project\garyhub-repo`；继续使用原来的 Windows OpenSSH、SSH 私钥和已知主机记录。无需复制应用代码、输入新的配置或安装服务器依赖。切换 Calendar 和 Tools/Lab 时会短暂不可用，请保持运行窗口打开。

安装器只有通过 HTTPS 和通知核验才报告 COMPLETE。若显示 STOPPED，保留末尾输出并反馈；不要绕过版本、源码或数据检查。包要求服务器实际运行 v1.3.5.3，GitHub 的合并状态不能替代部署核对。

## 新功能怎么使用

Todo List 的 New Todo 旁增加 **导入待办 / Import** 和 **AI 提示词 / AI Prompt**。

- 点击 AI 提示词，一键复制完整模板；把模板和你的材料发送给所用的 AI。提示词随中英文切换，并显示当前账号剩余待办容量。
- 点击导入待办，粘贴 AI 生成的 JSON，或上传 `.json` 文件。点击“解析并预览”，核对主待办、子要点、重复数量和同名提示，再确认导入。
- 新待办追加到末尾，保留已有内容和顺序。主待办与子要点保留独立完成状态，省略 done 时默认为未完成。
- 完全相同的标题、主完成状态以及按顺序排列的子要点文本和完成状态，视为重复；内部编号不参与比较。默认跳过，也可主动取消该选项。同名但内容不同的条目会提示并作为独立待办追加。
- 兼容现有“下载草稿”文件。文件中的编号在导入时重新生成，不覆盖原条目。
- 内容有错时保留输入并定位字段；整批校验成功后才写入。清单被另一页面改动时暂停导入，关闭窗口后重新加载，再用保留的导入内容重新预览。
- 导入内容只属于当前账号；切换账号会清除旧账号窗口内的草稿。管理员不会因此获得他人的待办。

## 支持的格式与限制

推荐格式：

```json
{
  "format": "garyhub-todos-v1",
  "todos": [
    {
      "title": "准备项目更新",
      "done": false,
      "points": [
        {"text": "核对需求和具体改动。", "done": false}
      ]
    }
  ]
}
```

也接受直接的待办数组、只有 todos 的对象、带 UTF-8 BOM 的文件，以及完整的单个 json 代码块。非空标题必填；points 可省略或为空数组。未知字段会报错，以免日期、备注等信息被静默丢弃；可先用 AI 提示词整理成子要点。

每账号累计最多 300 条待办，每条最多 100 个子要点。标题最多 160 字符，每个子要点最多 1,000 字符（沿用现有 JavaScript 字符长度规则）；文件/输入最多 2,000,000 字节，含编号的最终清单最多 1,800,000 字节。支持文字中的换行、引号、中文和路径；不会静默截断。

## 源码同步与 GitHub

服务器部署和 GitHub 推送是两个步骤。本包不会自动推送或合并。

本机仓库来源正确、工作区干净且源码匹配已审阅基线时，安装器会创建并提交 `update/garyhub-v1.3.5.4`。已有改动或已有分支会保留。源码同步警告不会撤销已经成功的服务器部署；完整更新源码和测试留在 `%LOCALAPPDATA%\GaryHub\updates\v1.3.5.4-r1`。

需要同步 GitHub 时，双击 `PUSH-TO-GITHUB.cmd`，再在打开的页面创建、审查和合并 PR。此操作不会再次部署服务器。

## 重试与回滚

- 成功后重跑同一入口不会重复部署或重复通知。
- 仅通知发布失败时重跑只重试通知步骤。
- `ROLLBACK.cmd` 恢复更新前的 v1.3.5.3 应用镜像，保留当前全部用户记录，包括更新后导入的待办。
- 检测到后续部署、有效配置变更或未完成的账号删除时，回滚会停止，避免覆盖后续工作。

正式数据和既有环境配置继续保留。备份只写入服务器受限目录，不进入 ZIP 或 Git。实际部署索引为 `/opt/my-services/garyhub-active-deployment.json`，本次状态记录为 `/opt/garyhub-update-v1.3.5.4-r1/deployment-state.json`。
