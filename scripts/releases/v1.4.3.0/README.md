# GaryHub v1.4.3.0 升级包（安装器 r2）

r2 修正 r1 在 3/8 隔离测试中将 Calendar 模拟 R2 预加载传给 Tools/Lab 的错误。Lab 没有 DATA_DIR，导致 fake-r2.cjs:5:35 启动失败；已按该条件在本地复现。现在按服务注入测试配置，本地运行器也不再给 Lab 人为补入 Calendar 环境。你的 r1 输出尚未切换正式服务或发布通知，无需回滚；请完整解压 r2 到新目录后双击 RUN-UPDATE。

要求服务器 Calendar 与 Tools/Lab 均实际运行 v1.4.2.0。包中包含安装、回滚、源码同步、R2 配置和网页操作指南，不需要保留旧升级包。

1. 完整解压 ZIP，双击 `RUN-UPDATE.cmd`。沿用已有 SSH 私钥；提示时输入私钥口令。
2. 等待核对版本、离线构建、合成数据测试、备份、切换、HTTPS 验证和站内通知核验。成功显示 `COMPLETE v1.4.3.0` 及实际通知人数。
3. 根据同目录 `CLOUDFLARE-R2.md` 开通私有 R2 桶及凭据，然后双击 `SETUP-R2.cmd` 输入配置。Secret 隐藏输入，不要发送给聊天或放入 GitHub。
4. 看到 `R2 READY` 后，用订阅用户或管理员打开 https://calendar.garyhub.uk/music/ 上传、选择音乐。R2 未配置时默认音乐仍可播放，额度限制已生效。

普通用户：最多 5 项固定开支、5 条待办，每条最多 10 个 points；已完成/停用的内容仍计数。已有超额内容不删除，可整理原内容。订阅与管理员保留原 300 / 100 上限。个人 MP3 最多 10 首，单首 20 MiB、合计 100 MiB，音频存于 R2，播放由浏览器直连。

本次不重启 VPN、不修改 Reading 或 Caddy。切换两个 Web 服务时会短暂重连。未知版本/源码/配置时停止；保留最后 `STOPPED` 输出，不要跳过检查。

恢复双击 `ROLLBACK.cmd`，回到 v1.4.2.0，保留当前记录及个人音乐；后续部署或受保护配置变化时会停止。旧版本不处理 R2 清理队列，恢复本版本后继续处理。

需要同步源码时双击 `PUSH-TO-GITHUB.cmd`，使用独立审查分支，不覆盖原工作区、不强推、不自动合并 main。服务器安装成功不等于 GitHub 已合并；源码准备完成也不等于服务器上线。

测试结论及明确未验证的部分见 `TEST-RESULTS.md`。
